# 授权发码流程（作者专用）

> 适用：Shinichi（1651452812@qq.com）、Fastrof（3530209532@qq.com）
> 工具：`发码工具.pyw`（图形界面，推荐）或 `tools/license_keygen.py`（命令行）
> 签名方式：**Ed25519 非对称签名**——程序里只有公钥，私钥只在你们手里

## 零、先保管好私钥

仓库根目录的 **`license_private.key`** 是签发激活码的唯一凭证：

- 它已经在 `.gitignore` 里，**不会被上传**
- 请**立刻备份**到 U 盘 / 密码管理器 / 另一台电脑
- 私钥丢了就再也发不了新码，只能换密钥、重发版本（老用户的码也会失效）
- 不要把私钥发给任何人，也不要把发码工具和私钥一起打包给别人

## 一、术语对照

| 软件里写的 | 实际含义 |
|---|---|
| 本机灵符 | 机器码（16 位，形如 `D6B1-411D-F9B1-414F`） |
| 许可咒文 | 激活码（机器码 + 有效期 + Ed25519 签名，约 130 字符） |
| 解开结界 | 激活 |

## 二、完整流程

```
用户安装 → 弹出「博麗神社 · 结界许可」
        → 复制「本机灵符」→ 邮件发给你们
你们    → 打开发码工具 → 粘贴机器码 → 生成 → 复制激活码 → 回信
用户    → 粘贴「许可咒文」→ 点「解开结界」→ 进入主界面
```

### 用户端怎么找机器码

- 首次启动的「结界许可」窗口里，金色大字就是本机灵符
- 点旁边的 **「收下灵符」** 按钮即可复制
- 也可以在「设置 → 神社登记」里看到

### 作者端怎么发码

1. 确认 `license_private.key` 在仓库根目录（或设置环境变量 `SCH_LICENSE_KEY` 指向它）
2. 双击 `发码工具.pyw`
3. 把用户邮件里的机器码粘到「用户机器码」
4. 选 **永久**，或选 **按天数** 填数字（如 365）
5. 点 **「生成激活码」**，窗口里会出现自检结果（应为 OK）
6. 点 **「复制激活码」**
7. 邮件回复用户

命令行方式（等价）：

```bat
python tools\license_keygen.py D6B1-411D-F9B1-414F
python tools\license_keygen.py D6B1-411D-F9B1-414F --days 365
python tools\license_keygen.py D6B1-411D-F9B1-414F --key D:\path\license_private.key
```

## 三、激活码长什么样

```
D6B1-411D-F9B1-414F-00000000-DVKUIEYYGGOCNEZKH4ZSLYQXBZLO24Q7OGD3VBKMM...
```

- 6 段，用 `-` 分隔：4 段机器码 + 1 段有效期（十六进制时间戳，`00000000` 表示永久）+ 1 段签名
- 全长约 130 字符，**复制粘贴整个串**即可，不要手动抄
- 老版本的短码（HMAC）已全部作废，需要重新发

## 四、回信模板

> 同学你好，激活码如下（整段复制，不要带多余空格）：
>
> ```
> <把激活码粘贴到这里>
> ```
>
> 打开程序 → 把激活码粘贴到「许可咒文」→ 点「解开结界」即可。
> 这个码只对你这台机器有效，换电脑或重装系统后机器码会变，到时再找我们。

## 五、校验用户发来的码

```bat
python tools\license_keygen.py <机器码> --check <激活码>
```

输出 `OK - 已激活（永久）` 或 `FAIL - 这个激活码不是本机的`。

## 六、规则和注意事项

1. **一机一码**：激活码绑定机器码，换机器/重装系统后机器码会变，需要重新发
2. **天数码从发码时刻起算**（不是从用户激活起算）
3. **只把码发给对应机器的主人**，不要群发同一个码
4. **私钥和发码工具绝对不能外传**，也不要放进安装包或公开仓库
5. 源码公开也安全：程序里只有公钥，没有私钥就签不出新码
6. 用户激活失败常见原因：
   - 激活码没复制完整（130 字符，少一段就失败）
   - 机器码不匹配（用了别人机器的码）
   - 天数码已过期
   - 系统时间被改过（会提示试用作废）
