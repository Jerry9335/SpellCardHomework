> 状态：**规划中，未动代码**

1. 用户不用天天盯 GitHub，程序自己能发现新版本

4. 顺手修掉 1.0.1 遗留的小问题，补齐几个高频需求

## 三、详细需求

### 3.1 自动检查更新（P0）

**东方话术**：`文文的号外`（射命丸文送报纸 = 检查更新）

#### 功能点

1. **检查来源（可选渠道）**
   - **GitHub**：`https://api.github.com/repos/Jerry9335/SpellCardHomework/releases/latest`
   - **Gitee**：`https://gitee.com/api/v5/repos/jerry6663/SpellCardHomework/releases/latest`
   - 用户可在设置里选择渠道：
     | 选项 | 行为 |
     | --- | --- |
     | 自动（推荐） | 先查 Gitee（国内快），失败再查 GitHub，取版本更高的一个 |
     | 仅 Gitee | 只查 Gitee，失败就静默 |
     | 仅 GitHub | 只查 GitHub，失败就静默 |
   - 读取 `tag_name`（如 `v1.0.2`）与 `html_url` / `browser_download_url`
   - 与本地 `settings.APP_VERSION` 比较（语义化版本）
   - 只检查 **稳定版**，不检查 draft / prerelease

2. **检查频率（用户可设定）**
   - 预设：启动时 / 每天 / 每 3 天 / 每周 / 自定义（小时）
   - 默认：**每 24 小时**，启动时如果距上次检查超过间隔才检查
   - 检查在后台线程执行，**不能阻塞启动和主界面**

3. **暂停更新（小日历）**
   - 设置里提供「暂停报信到」：
     - 快捷选项：1 天 / 3 天 / 7 天 / 30 天
     - 小日历：点选任意日期
   - 暂停期间不自动检查，但**手动「立即检查」仍然可用**
   - 暂停到期后恢复，并立即检查一次

4. **发现新版本时**
   - 主界面顶部或状态栏出现一条提示条：`文文带来了号外：v1.0.2 已发布`
   - 弹窗展示：
     - 新版本号、发布日期
     - Release 说明（GitHub 的 body，纯文本渲染）
     - 按钮：`前往下载`、`稍后提醒`、`暂停到某天`
   - 不自动下载、不自动安装（见「不做的事」）

5. **失败处理**
   - 网络失败 / 被墙 / API 限流：静默失败，不弹错误框
   - 记录到 `boot.log` 或独立的 `update.log`
   - 下一次到期再试

#### 配置项（config.json 新增）

```json
{
  "update_enabled": true,
  "update_interval_hours": 24,
  "update_last_check": 0,
  "update_snooze_until": 0,
  "update_channel": "auto",
  "update_repo": "Jerry9335/SpellCardHomework",
  "update_gitee_repo": "jerry6663/SpellCardHomework",
  "update_manual_url": "https://github.com/Jerry9335/SpellCardHomework/releases/latest"
}
```

#### 界面位置

- 设置页新增一节：`文文的号外（自动检查更新）`
  - 更新渠道下拉（自动 / Gitee / GitHub）
  - 开关、频率下拉、暂停到（日期按钮 + 小日历）、立即检查按钮
- 关于页显示：当前版本、上次检查时间、检查结果

### 3.2 Windows Toast 通知（P0）

**东方话术**：`式神的传讯`（式神替你传话 = 系统通知）

#### 功能点

1. **通知场景**（可分别开关）
   | 场景 | 默认 | 内容示例 |
   |---|---|---|
   | 发现新版本 | 开 | `文文：v1.0.2 已发布，点我去看看` |
   | 试用即将到期 | 开 | `紫：试用到后天就结束了哦` |
   | 试用已到期 | 开 | `灵梦：结界要关了，该来登记了` |
   | 自动答题完成/中断 | 关 | `魔理沙：这一轮退治完了` |
   | 单题作答完成 | 关 | `灵梦：答案出来了` |

2. **技术实现**
   - 用 Windows 10/11 的 Toast（WinRT `Windows.UI.Notifications`）
   - 通过 PowerShell 调用 WinRT，不引入新的 Python 依赖
   - 需要有效的 **AppUserModelID**（`Shinichi.SpellCardHomework`）
     - 安装包创建的开始菜单快捷方式要写入同一个 AUMID（Inno Setup `[Icons]` 的 `AppUserModelID` 参数）
     - 源码运行（pythonw）可能无法弹 Toast → 自动降级为静默
   - 失败不影响主流程，捕获所有异常

3. **免打扰**
   - 安静时段（默认 23:00–08:00）不弹通知
   - 同一事件 24 小时内最多一次（去重）
   - 设置里可关闭全部通知

#### 配置项（config.json 新增）

```json
{
  "toast_enabled": true,
  "toast_update": true,
  "toast_trial": true,
  "toast_auto": false,
  "toast_answer": false,
  "toast_quiet_start": 23,
  "toast_quiet_end": 8
}
```

### 3.3 补充需求（P1/P2）

#### P1

1. **单实例运行**
   - 用 Windows 命名互斥量（`CreateMutexW`）
   - 第二个实例启动时，激活已有窗口并退出

   - 失败：分类提示（401 / 404 / 超时 / 额度）

3. **试用到期提醒**
   - 剩余 2 天、1 天、0 天各弹一次 Toast
   - 主界面状态栏同步提示

#### P2

4. **设置导入/导出**
   - 导出 JSON（不含 API Key，或提供「包含密钥」勾选）
   - 导入时校验字段，合并到当前配置

5. **日志轮转**
   - `boot.log`、`usage.jsonl` 超过 2 MB 自动归档（保留最近 3 份）

   - 设置里填「每月香火钱上限」

### 3.4 自动答题稳定性修复（P0/P1）

对 `app.pyw` 的全自动循环和 `modules/web.py`、`modules/prompts.py` 做了一轮代码审查，
以下是确认存在或高风险的问题（按严重程度排序）。

#### P0：会导致停住、答错或重复提交

| # | 问题 | 影响 | 位置 |
|---|---|---|---|
| W1 | 多选答案把单词字母当成选项 | `CHOICE: A and C` 会解析成 `A,A,N,D,C`，`none of these` 会解析成 `N,O,N,E…`，多选直接点错 | `modules/prompts.py::parse_web_answer` |
| W2 | 多选重复提交检测只比较第一个字母 | 上次选 A、C，这次选 A、D 会被判成「同一个答案」，直接跳过 | `app.pyw` `_web_step` 里 `_sig = … choice …` |
| W3 | 一题处理不了就退出整个全自动 | `_web_skip()` 返回 False，主循环 break；一道不支持的题就收工 | `app.pyw::_web_skip` |
| W4 | 模型请求异常时无限重试同一题 | 无失败计数、无退避，API 故障时会持续重复请求 | `app.pyw::_web_step` 失败分支 `return True` |
| W5 | 「收工」无法中断进行中的模型请求 | `chat_once` 超时 180 秒且不支持 cancel，按钮会长时间没反应 | `modules/llm.py::chat_once` |
| W6 | 复选框已勾选时再点会取消 | 多选前没清空旧勾选，`pick_choice` 也不判断 checked | `modules/web.py::pick_multi / pick_choice` |
| W7 | 填空只验证「非空」 | 清空失败、旧答案残留也会被当成成功，可能重复提交旧答案 | `app.pyw::_web_fill` |
| W8 | 页面一直没题时无限等待 | 纯图片题 / 加载失败时循环显示「等题目出现」，不会跳过 | `app.pyw::_web_step` 空状态分支 |
| W9 | 原生 `<select>` 被处理两次 | 2193 和 2225 两段逻辑重复，可能覆盖已选值；多个 select 只处理第一个 | `app.pyw::_web_step` |
| W10 | 多小问下一问出现慢就停机 | `_web_wait_change(timeout=4)` 超时后判「没有下一题」并结束 | `app.pyw` 判分/答错后的分支 |

#### P1：容易答错或体验差

| # | 问题 | 影响 | 位置 |
|---|---|---|---|
| W11 | 判分反馈只等 8 秒 | Pearson 慢时误判「没看到判分结果」并跳过 | `_web_feedback` |
| W12 | 点击不校验成功 | `click_text` 不检查按钮是否禁用；`_web_dismiss` 点任意 OK，可能误点 | `web.py::click_text / _web_dismiss` |
| W13 | 答案格式未归一化 | `x=3`、`3.0`、`1,000`、带单位、`or` 多解、分数/小数互换都会填错 | `_web_fill` / `latex` |
| W14 | 无字母选项的排序回退 | radios + checks 合并按位置取，混合题型可能点错 | `web.py::pick_choice` |
| W15 | 多标签连错页面 | `connect()` 取第一个 Player 页，换页后不重选 | `web.py::connect` |
| W16 | 高 DPI / 浏览器缩放坐标偏移 | 真实鼠标点击与截图可能偏 | `web.py::focus_field / capture_clip` |
| W17 | 练习题弹窗答对后直接停机 | `inDialog` 为真就 return False，真题若是弹窗式反馈会被误停 | `_web_step` 判对分支 |
| W18 | 粘贴覆盖剪贴板 + Ctrl+A 风险 | 用户剪贴板被占；富文本编辑器可能全选整页 | `web.py::paste_math / clear_field` |
| W19 | 无验证码 / 登录过期检测 | 会话失效或人机验证时一直报错 | `_web_loop` |
| W20 | 翻译线程与下一题竞态 | 上一题翻译可能追加到新题面板 | `_web_step` 翻译线程 |
| W21 | 下拉框部分成功也提交 | 多个下拉框只选中一部分仍继续 | 下拉框分支 |
| W22 | 矩阵只填第一个目标 | 矩阵弹窗没开就失败跳过 | 矩阵分支 |

#### P2：清理与健壮性

- `pick_choice` 里重复的 `if not cand` 死代码
- `_part_of` 定义未使用
- `_web_seen / _web_prev / _web_try` 无上限，长时间运行内存增长
- 错误只写状态栏，没有落盘日志
- 练习题 / Review 页 / 无 Check 页的处理策略不统一

#### 修复方向（概要）

1. **解析器**：`CHOICE` 只认 A–H 的独立字母 token（按非字母切分后过滤长度 1），`DROPDOWN` 只取第一个连续数字段
2. **多选**：`_sig`、`_web_prev`、答错提示都使用完整 `choices` 列表
3. **跳过策略**：新增「遇到不支持的题：跳过并继续 / 停下」设置，默认继续
4. **失败计数**：模型连续失败 N 次（如 3 次）后退避并跳过，不无限重试
5. **可取消**：Web 答题改用支持 cancel 的流式调用，或在 `chat_once` 前后检查 `web_stop`
6. **填空校验**：归一化后比对期望值（去空格、去 `x=`、统一小数/分数）
7. **超时**：无题 30 秒、下一问 15 秒、判分反馈 15 秒
8. **单选/多选**：先读 checked，已选则跳过；多选前清空旧勾选
9. **测试**：为 W1/W2/W6/W7/W8/W10 增加回归用例

## 五、技术方案

| 模块 | 职责 |
|---|---|
| `modules/update.py` | GitHub API 请求、版本比较、检查节流、状态持久化 |
| `modules/toast.py` | WinRT Toast 封装 + 安静时段 + 去重 |
| `modules/single_instance.py` | 命名互斥量 |
| `modules/calendar_dialog.py` | 自制月历（Tkinter，无第三方依赖） |
| `app.pyw` | 设置页新增分区、更新提示条、定时器 |
| `installer/` | 快捷方式 AUMID、版本号 1.0.2 |

**版本比较**：`1.0.2` vs `1.0.1` 用元组比较，兼容 `v` 前缀与 `-beta` 后缀（预发布不提示）。

**线程模型**：检查更新与 Toast 都在后台线程；结果通过现有 `self.q` 队列回主线程，**禁止跨线程直接操作 Tk**。

**依赖**：不新增第三方依赖（Toast 走 PowerShell）。
